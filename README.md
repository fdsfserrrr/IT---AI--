数据管道与研究基础设施——量化系统的地基工程
程序员做量化，最容易犯的错误是直接冲进策略开发，忽略了数据层和研究基础设施的搭建。华泰柏瑞量化团队的实践表明，投研系统的完备程度正在成为量化能力高下的分水岭，整套架构分为数据层、文本处理层、研究模型层、组合风险层和工程知识沉淀层五个层级，各模块相互衔接协同运转。数据层的质量直接决定了后续所有环节的天花板。

多源数据接入的工程决策
量化数据管道的第一个技术决策是数据源的选择与容错。SolidRockQuant 的设计思路值得借鉴：以 AKShare 为主通道、新浪为自动回退，同时接入 Tushare Pro 和 Baostock，架构预留 Wind 等商业接口。这种多源策略解决的不是“哪个数据源更好”的问题，而是“当某个免费数据源被限流或接口变更时系统如何继续运行”的工程韧性问题。

数据规范化的一个关键细节是复权处理。前复权价格会随每次除权事件动态漂移，破坏回测的可复现性。正确的做法是只存储原始价格加后复权因子，由计算层按需推导前复权价格。本地缓存的写入策略同样需要工程考量：Parquet 原子写入配合 DuckDB 参数化读取，增量更新保持幂等，避免重复拉取和写入冲突。

因子研究的基础设施化
传统因子研究高度依赖研究员个人经验，因子代码散落在 Notebook 中，难以复用和审计。华泰柏瑞的解法是将因子研究基础设施化：Factor 基类定义统一的因子接口，面板容器（宽表）承载截面数据，去极值、标准化、行业市值中性化等预处理步骤被封装为可复用组件。因子评价指标涵盖 RankIC、ICIR、t 值、分位数分层回测和多空价差，分析结果与回测共用同一套实验追踪系统。

实验追踪是 Agent 迭代的“记忆层”。每次回测或因子分析自动记录参数、配置、数据快照和指标，存储在 SQLite 中零部署运行。Agent 可以查询对比历史实验，回答“上次跑的动量策略和这次比哪个好”这类问题。没有实验追踪的量化研究，本质上是在黑暗中摸索。

面向 Agent 的接口设计
程序员用 AI 做量化的一个现实困境是：vnpy、qlib、backtrader 这些优秀框架都是“给人用”的，AI Agent 接入时处处碰壁——报错信息人类能猜懂，Agent 只会反复重试；回测结果埋在日志里，Agent 无法可靠读取。解决这个问题的技术方向是将 MCP Server 作为一等公民接口，为 Agent 暴露数据获取、回测、因子分析、实验查询等结构化工具。结构化输出采用统一 JSON 信封加 Markdown 报告，错误码稳定且附带可执行的修复提示。前视偏差检测以 AST 静态检查的方式在回测前自动拦截 shift(-n)、bfill 等 LLM 常见错误。

数据管道和研究基础设施是量化系统中最不性感但最关键的环节。地基不牢，后面所有的策略创新都是沙上筑塔。
